Vehicle dynamics simulator for Formula Student cars

A real-time simulator I am building from the physics core up for Formula Student cars, on the way from a design tool for one car to a simulator that calibrates itself from real data and helps design the next vehicle.

Unity 6 / C#Python ~16k lines C#~7k lines Python Since 2025

Demo

What it does

Physics core

1 kHz physics loop. The rate was chosen from a convergence study: at 200 Hz, steady-state lateral grip was under-predicted and transient wheelspin was suppressed.

Tires

Pacejka Magic Formula 6.1 with coefficients taken directly from a measured .tir file: load sensitivity and combined slip, kept inside the fitted slip range.

Powertrain

Combustion engine with sequential gearbox, quickshifter and clutch slip, plus an electric motor preset. Engine maps from analysis results or dynamometer measurements.

Chassis

Suspension with camber change and anti-roll bars, Ackermann steering geometry, aerodynamic downforce and drag.

Human in the loop

Force-feedback steering wheel driven by tire aligning torque, so a driver can feel the car before it is built.

Automated testing

Headless batch harness with ~24 scenarios (acceleration, skidpad, endurance, …) and parameter overrides from environment variables, so design variants run without touching the scene.

Engineering data

100 Hz telemetry exported to labeled spreadsheets: engine-speed distribution, longitudinal/lateral acceleration, gear occupancy, steering torque.

Autonomy stack

Python stack connected over TCP: LiDAR + camera (YOLO trained on synthetic data rendered by the simulator), EKF-SLAM, racing-line optimization and lateral MPC. PicoSim Autonomous

How it compares

Commercial vehicle simulators set the standard for model fidelity. This project does not claim to match them today. Its value is in what a fully open, end-to-end tool makes possible.

Tool typeStrengthWhere it falls short for this goal
Commercial vehicle dynamics
CarSim, IPG CarMaker		 Validated multibody models, K&C tables, HIL support, industry standard. Closed models and licensed seats; the model can be tuned but not rewritten. Self-calibration and design loops have to be built around it.
Lap-time simulators
quasi-steady-state		 Very fast; good for early concept trade-offs. No transient dynamics, no driver in the loop, no controller testing.
Racing games / driving sims Convincing feel, good graphics, wheel support. Not engineering tools: internals are not documented, parameters cannot be traced to sources, little structured data output.
Autonomy simulators
e.g. CARLA		 Sensors, scenarios, open source. Vehicle dynamics are not the focus; tire and powertrain models are simplified.
This project Full source control from tire model to telemetry; one tool for driver-in-the-loop, autonomy and batch design studies. Not yet validated against real vehicle data; suspension kinematics simplified (see roadmap).

What makes it different

  • Every number has a source. Physics constants come from measurements, standards or literature, documented next to the code, with no hand-tuned "feel" factors. This is what makes calibration against real data meaningful.
  • Accuracy is checked, not assumed. Numerical settings such as the integration rate are chosen from convergence tests run through the harness.
  • One model, three uses. The same vehicle model serves a human driver, an autonomous stack and headless design studies, so results stay consistent across them.
  • Built for the design loop. Parameter overrides, batch runs and spreadsheet export already let one design change go from idea to data without manual steps. This is the base for automatic calibration and optimization.
  • Fully open. No license limits on seats, runs or model changes: the model can be extended exactly where the car needs it.

Roadmap

Goal: a simulator that can be trusted for real vehicles, calibrates itself from real data, and uses that model to design the vehicle.

  1. PHASE 1

    Foundation done

    • Drivable car with 1 kHz physics chosen by convergence study and MF 6.1 tires from measured coefficients
    • Combustion and electric powertrains, aerodynamics, force-feedback steering
    • Batch test harness, 100 Hz telemetry with spreadsheet export
    • Single vehicle parameter dataset (JSON); anti-roll bars acting through tire loads
  2. PHASE 2

    Vehicle model fidelity & validation in progress

    • Hardpoint-based K&C solver: bump steer, roll centre, anti-dive/squat, bump stops, unsprung mass
    • Member loads as an output for structural design
    • Automated KPIs from standard manoeuvres (steady-state cornering, sine-with-dwell)
    • Comparison against real logs from PicoSim Telemetry and a commercial reference model
  3. PHASE 3

    Self-calibrating simulation planned

    • Identify model parameters automatically from real driving and test data
    • Model improves as data accumulates, without forgetting what it already learned
    • Staged validation: software, hardware, then vehicle in the loop
  4. PHASE 4

    Simulation-based design planned

    • Physics as a standalone library with a C API: fast headless runs from Python, FMU export
    • Optimize battery capacity, motor power, vehicle size and suspension kinematics on the calibrated model
    • Derive component requirements (boundary conditions) from target performance, with battery and thermal models
  5. PHASE 5

    Beyond the track planned

    • Road scenarios and traffic for real-road vehicles
